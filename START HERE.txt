BUG 1 - "APPLY DDL TO TARGET" FAILED: unrecognized exception condition - NOW FIXED
-------------------------------------------------------------------------------------
Oracle's `e_invalid_status EXCEPTION;` declares an exception local to the
routine, later both raised (`RAISE e_invalid_status;`) and caught by name
(`EXCEPTION WHEN e_invalid_status THEN ...`). An earlier round already
rewrote the RAISE side; nothing had ever touched the WHEN side. Postgres
has no user-defined exception type at all, only SQLSTATE condition
codes, so it tried to parse "e_invalid_status" itself as a real
condition name and rejected the entire function/procedure outright with
"unrecognized exception condition" -- a compile-time failure, not a
runtime one. Every routine declaring, raising, and catching its own
named exception failed "Apply DDL to Target" the moment it got this far.

This build makes both sides agree on a synthetic SQLSTATE code minted
per declared exception: `RAISE e_invalid_status;` becomes
`RAISE EXCEPTION 'e_invalid_status' USING ERRCODE = 'U0001';`, and
`WHEN e_invalid_status THEN` becomes `WHEN SQLSTATE 'U0001' THEN`. Two
different exceptions declared in the same routine get two different
codes, so multiple WHEN clauses still branch correctly.

MySQL, SQL Server and Db2 needed no change -- all three already handle
this case correctly (a real mapping or a clear flag), so this was a
PostgreSQL-only gap.

Re-running "Apply DDL to Target" on this build (after re-running "2.
Convert Schema" first - see above) picks up from where it left off. Any
other routine declaring, raising, and catching its own named exception
anywhere in the schema is covered by this same fix.
